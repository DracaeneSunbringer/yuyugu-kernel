# 鱼鱼谷自动化内核 (yuyugu-kernel)

面向 `52dmeme.com` 宠物世界（鱼鱼谷）的全自动托管程序，基于 Node.js 原生模块实现，无任何第三方依赖。

覆盖农田种植、牧场养殖、工坊加工、货船采购、行情出货、体力调配、挖矿钓鱼、邻居出访、宠物养成、竞技场配装及每日幻彩；另内置**默认关闭**的「大肥鱼修仙记」独立托管模块。

## 快速开始

### 1. 环境要求

仅需安装 **Node.js >= 22**（无需 `npm install`）：

```bash
git clone https://github.com/DracaeneSunbringer/yuyugu-kernel.git
cd yuyugu-kernel
node -v
```

可选执行测试集验证本地环境：

```bash
npm test
```

### 2. 配置 Cookie

浏览器登录 `https://52dmeme.com/pets`，按 `F12` 打开开发者工具获取登录 `sid`：
- **方式 A（Network）**：打开 `Network` 面板，任选一个 `/api/pet/world` 请求，复制请求头中的 `Cookie`（形如 `sid=xxxx`）；
- **方式 B（Application）**：打开 `Application -> Cookies -> https://52dmeme.com`，复制 `sid` 对应的 `Value`（程序会自动补全 `sid=` 前缀）。

将 `.session.example.json` 复制为 `.session.json` 并填入（`.gitignore` 已默认忽略所有 `.session*.json`）：

```json
{
  "cookie": "sid=粘贴你的sid值"
}
```

### 3. 只读预检

首次启动前建议执行一次只读检查（`--dry-run` 在底层拦截所有非 `GET` 请求，不会改动账号状态）：

```bash
node cli/live-daemon.mjs --dry-run --once
```

输出 JSON 中 `controllerStatus` 为 `"shadow-ready"` 即表示登录态与规划正常。

## 部署运行

### Linux / macOS 后台运行

```bash
mkdir -p logs/live
nohup node cli/live-daemon.mjs \
  --self-ids 你的UID \
  </dev/null >> logs/live/live-daemon.main.out 2>&1 &
```

- 发育期如需自动买地、扩建谷仓与升级工具（仅在预计回本周期 `<= 72h` 时触发），加上 `--allow-capex`。
- 若只运行本岛生产、不扫描邻居也不出访偷菜，加上 `--domestic-only`。

### systemd 常驻守护（Linux 推荐）

新建 `~/.config/systemd/user/yuyugu.service`：

```ini
[Unit]
Description=Yuyugu Kernel
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/path/to/yuyugu-kernel
ExecStart=/usr/bin/node cli/live-daemon.mjs --self-ids 你的UID
Restart=always
RestartSec=10
StandardOutput=append:/path/to/yuyugu-kernel/logs/live/live-daemon.main.out
StandardError=append:/path/to/yuyugu-kernel/logs/live/live-daemon.main.out

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now yuyugu.service
```

### Windows (PowerShell)

```powershell
New-Item -ItemType Directory -Force logs/live | Out-Null
Start-Process node `
  -ArgumentList "cli/live-daemon.mjs --self-ids 你的UID" `
  -RedirectStandardOutput "logs/live/live-daemon.main.out" `
  -RedirectStandardError "logs/live/live-daemon.main.err" `
  -WindowStyle Hidden
```

### 常用参数与日常维护

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--session <path>` | `./.session.json` | 指定 Cookie 文件路径 |
| `--self-ids <id>` | 空 | 自身数字 UID，巡检出访时自动跳过 |
| `--domestic-only` | 关 | 纯内政模式，不拉取邻居列表、不执行出访 |
| `--allow-capex` | 关 | 回本周期合理时自动买地与升级建筑、工具 |
| `--no-capex` | 关 | 强制关闭自动买地与基建升级 |
| `--enable-xian` | **关** | 开启「大肥鱼修仙记」（`state.xs` 修仙）独立日常托管（也可设 `MEME_ENABLE_XIAN=1`）；与小岛金币、体力、仓库完全隔离，序章选灵根与弹幕斗法/切磋全程让位手操 |
| `--xian-break-mode <mode>` | `smart` | 境界冲关策略：`smart`（默认，综合药园等级、培元丹存量、灵根成长与 9 层修为垫子的联合策略）、`eager`（丹药与修为齐备即冲）、`manual`（只攒丹药与修为，不自动冲关；也可设 `MEME_XIAN_BREAK_MODE`） |
| `--xian-auto-fuse` | **关** | 筑基后是否自动尝试变异灵根融合（也可设 `MEME_XIAN_AUTO_FUSE=1`，**默认关闭**，原因与手操建议见下文） |
| `--xian-fuse-target <el>` | `auto` | 开启 `--xian-auto-fuse` 时限定目标变异属性：`auto`（默认，按五元环最大匹配选路）或 `ice` / `thunder` / `wind` / `lava` / `poison`（也可设 `MEME_XIAN_FUSE_TARGET`） |
| `--data-dir <dir>` | `./logs/live` | 日志、排期表、对手面板与文件锁目录 |
| `--check-update` | 关 | 立即检查远端仓库是否有新版本并输出更新摘要后退出 |
| `--no-update-check` | 关 | 关闭后台自动版本更新检查（也可设环境变量 `MEME_NO_UPDATE_CHECK=1`） |
| `--update-webhook <url>` | 空 | 发现新版本时自动推送通知 Webhook（兼容飞书/企微/钉钉/通用 JSON，同版本自动去重，也可设 `MEME_UPDATE_WEBHOOK_URL`） |
| `--dry-run` | 关 | 只读模式，拦截一切 `POST` 请求 |
| `--once` | 关 | 执行单轮后打印结果并退出 |

查看日志、检查更新与优雅停止：

```bash
tail -f logs/live/live-daemon.main.out
npm run check-update
kill -TERM $(cat logs/live/live-daemon.main.pid)
```

> **自动更新提醒**：常驻运行时，程序每 2 小时在非出访窗口静默检查 GitHub 主分支 `package.json`。一旦发现新版本（如问题修复或策略改进），会在日志中打印醒目更新横幅、在每轮状态行末尾附带 `[有新版本 vX.Y.Z -> git pull]` 提示，并在检测到本地已 `git pull` 但尚未重启时提醒重启进程生效；网络不可达时静默跳过，不影响托管运行。

## 收益来源

鱼鱼谷的工坊次数、每日全价出货额度、体力和货船库存彼此制约，按固定优先级拆开执行容易浪费稀缺配额。本程序将各模块放在同一套估值下统一调度，主要收益来自五部分：

1. **工坊配额与货船差价**  
   工坊每岛日（4 小时，`22:00–08:00` 静潮期停表）限加工 80 次。程序按单位工坊次数和体力的净增值对全部配方（含多步合成链路）排序，优先排果酱、果酒、爆米花、皇冠等高毛利产物，避免被面粉、沙拉占满额度。当工坊尚有余量且货船刷出低价玉米、小麦、矿石、羊毛时，自动买入原料加工赚取差价；80 次用满后自动停止按加工价采购。

2. **跨期报价与星级分流**  
   收购价每 4 小时轮换，单日出售过多会触发 `100% -> 85% -> 70%` 阶梯折价，单轮抛售过猛还会压低次轮价格。程序结合当前报价与在途产量决定出货时机：若次日产量已够填满次日全价档，当期遇到高价即落袋，避免拖到次日掉入折价档。由于工坊成品不继承原料星级，出售原作物时按 `金星 -> 银星 -> 普通` 优先吃满全价额度，普通品质留给工坊加工。

3. **体力边际核算与预留**  
   挖矿（含买炸弹）、钓鱼、工坊和出访共用体力。程序实时比较 1 点体力的边际产出与仓库作物、货船食物、咖啡（15,000 金币，可突破体力上限）的单点成本，仅在净收益为正时补体。临近计划出访时间会自动锁住所需保底体力，防止被挖矿提前耗空。

4. **保护期卡点出访与期望过滤**  
   邻居作物成熟后有 30 分钟保护期。后台巡检记录解锁时间，临近解锁前自动中断耗时计算、补足体力、切换克制装备并准时发包。对有守卫的岛屿，综合计算未发现（2 倍）、战胜（3 倍）、平局、战败罚款及盗贼道具成本的数学期望，负期望目标直接跳过；出访结束后自动切回驻守防御装。

5. **养成、针对性配装与日常保底**  
   自动完成宠物喂食、清洁、互动、开箱与攻速断点加点；竞技场与守卫战前根据历史记录中的对手属性，在本地模拟选出最高胜率配装；每日按 `22:30` 开奖周期自动检查并购买一注 10 金币幻彩保底。

## 大肥鱼修仙记（独立修仙模块）

「大肥鱼修仙记」使用独立的修仙灵力（`xs.en`，上限 `100`，每 `6` 分钟自然恢复 `1` 点）与灵石（`xs.stone`），**零消耗**小岛金币、体力与仓库物品。模块默认关闭，传入 `--enable-xian`（或设环境变量 `MEME_ENABLE_XIAN=1`）后按以下边界托管：

### 1. 自动执行与手操让位边界

- **全程交由玩家手操的部分**：
  - **序章与初始测灵根（`st < 4`）**：未走完序章「商会来信」并选定初始灵根前，程序保持静默待机（`prologue-manual-standby`），绝不代选灵根。*（开局参考：灵根越少前期打坐倍率越高，越多后期融合上限越高；单灵根仅能修本系功法但弹幕伤害享受 `×1.5` 专精加成，其中金系 `庚金剑诀` 单体秒伤最高、水系 `沧澜诀` 全屏追踪最省心。）*
  - **论剑台闯关与 NPC 切磋**：弹幕玩法为纯前端实时操作，且单点灵力的灵石收益（论剑台 `4~17` 灵石/灵力，NPC 每日首胜切磋 `1.5~2.5` 灵石/灵力）远低于中后期灵药园种植（`8.1~85` 灵石/灵力），程序不会自动发起斗法；当检测到玩家正在手动闯关或切磋（`xs.fight` 活跃）时自动让位跳过。
- **自动托管的部分**：
  - **灵药园种收与 `100%` 双倍采摘**：自动买种、播种、按三阶段补满 `3` 次浇水、灵泉打水，并在灵力充裕时渐进除草扩田；利用服务端确定性计数规则（`xs.log % 4 === 3` 采摘必得 `2` 株仙草），每次 `xsHarvest` 前自动编排合法前置动作对齐模数，稳定吃满双倍收成。
  - **丹房满成色守火（固定 `q=2` 一炉三丹）**：自动起炉并守满火候稳拿上品一炉 `3` 颗丹药；每日优先炼服一炉回灵丹（耗 `5` 灵力出 `3` 颗共回 `+90` 灵力，吃满每日 `3` 颗上限净赚 `+85` 灵力），药园未满 5 级前优先炼服培元丹（`+40` 药园经验/颗，一炉 `+120` 经验）加速解锁毕业作物 `雷竹`。
  - **藏经阁打坐与功法预学**：自动维护每 `30` 分钟一轮的蒲团起身结算与续坐（`0` 灵力消耗），并在灵石充裕时自动学齐当前灵根可修习的功法。

### 2. 境界冲关策略（`--xian-break-mode`）

每次突破大境界成功率为 `60%`，需消耗 `当前境界序号 + 1` 颗培元丹，失败会扣除当前 `30%` 修为；而培元丹在药园满级前又能直接提供 `+40` 药园经验，因此培元丹用途、药园等级与当前溢出修为之间存在明确权衡：

- **`smart`（默认）**：
  1. **药园 5 级优先**：药园未满 5 级（未解锁 `雷竹`）前，培元丹优先用于冲刺药园等级；仅对 `1` 颗丹即可尝试的「炼气 → 筑基」在开启自动融合或多灵根高成长路线时提前放行，不在药园毕业前消耗多颗培元丹硬冲金丹及以上（尤其单/双灵根升境后基础修炼倍率反而衰减）。
  2. **余力炼丹与 `9` 层免税垫子**：药园满级后，仅在已开垦药田全部种满浇完且灵力仍有富余时才投炉炼制冲关所需的培元丹；等待丹药期间继续免费打坐，在 `9` 层自然攒出 `>= 1.43 × 突破线` 的修为垫子（即便冲关失败扣 `30%` 仍高于突破线，下一炉丹出炉即可立刻再冲）。
  3. **蒲团在途修为护盾**：当 `9` 层本体修为已达标且蒲团仍有在途修为时，严格按 **先 `xsBreak` 冲关、后 `xsRise` 起身** 顺序发包——成功则将蒲团在途修为直接带入新境界 `1` 层，失败则全额免受 `30%` 扣减。
- **`eager`**：只要 `9` 层修为达标且背包培元丹够数即立刻冲关（同样保留先冲关后起身的护盾顺序）。
- **`manual`**：程序仅按需储备培元丹并继续免费打坐攒修为，从不自动发起冲关，由玩家自行点击突破。

### 3. 灵根融合：为什么默认关闭，以及手操方向与防坑提醒

#### 为什么默认关闭（`--xian-auto-fuse` 默认关）

1. **永久不可逆**：服务端 `xsFuse` 一旦成功，会直接从角色基础灵根列表（`roots.e`）中永久移除参与合成的两条基础灵根并写入变异灵根（`roots.v`），**没有任何回退、拆分或重洗道具**，且变异灵根无法再次参与融合。
2. **变异流派互斥**：三灵根、五灵根账号存在多条互斥的合成分支，直接决定账号最终可学习的变异弹幕功法与符卡手感，属于不可逆的流派选择，因此默认交由玩家决定；若希望全自动合成，可显式加上 `--xian-auto-fuse`（并可用 `--xian-fuse-target` 指定目标变异属性）。

#### 手操融合收益与方向建议

- **全境界正收益**：任意一次合法融合都会使灵根总数 `-1` 并令每大境界成长系数额外 `×(1 + 0.12 × 变异数)`，在筑基至渡劫的**所有境界**打坐倍率均严格高于融合前。其中**双灵根融合成单变异灵根**后，不仅修炼倍率全面反超天生天灵根（筑基 `1.90x` vs `1.70x`，越往后差距越大），还会额外激活单灵根专属的 **`×1.5` 功法伤害加成**。
- **五元环相邻法则**：只有五元环 **`金 — 水 — 木 — 土 — 火 — 金`** 上相邻的两条**基础灵根**才能融合：
  - `金 + 水 → 冰`（`玄冰诀`：高速冰锥齐射）
  - `火 + 金 → 雷`（`紫霄雷法`：高速落雷）
  - `水 + 木 → 风`（`御风诀`：大角度扇面风刃）
  - `土 + 火 → 熔`（`熔岩诀`：高单发伤害重弹）
  - `木 + 土 → 毒`（`万毒经`：带自动追踪的散射毒雾，手操弹幕容错率极高）
- **按初始灵根数的手操路线**：
  - **单灵根**：天生单系专精（自带 `×1.5` 弹幕加成且省下全部融合丹药直冲 5 级药园），无需也无法融合。
  - **双灵根**：若两条灵根在五元环上相邻，筑基后直接合为**单变异灵根**即为完全体；若不相邻（如金木、水火）则无法融合。
  - **三灵根**：若三条相连（如 `火 — 金 — 水`），可在两对相邻组合中按偏好的变异功法二选一（合 `雷` 留水，或合 `冰` 留火），修炼倍率完全一致。
  - **四灵根（重点防废号提醒！）**：四条基础灵根在五元环上必然连成一条 4 节点折线（缺 1 系，例如缺土时为 `木 — 水 — 金 — 火`）。**第一刀绝对不要融合正中间那一对**（上例中的 `水 + 金 → 冰`）！一旦先合掉中间边，剩下的首尾两端（`木` 与 `火`）在五元环上互不相邻，会**永久断绝第二次融合**，卡死在「1 变异 + 2 杂灵根」（渡劫倍率从双变异的 `4.69x` 跌至 `2.85x`）。**正确做法**：分两次融合**首尾两侧配对**（上例 `木+水→风` 与 `金+火→雷`，先后不限），稳拿**双变异灵根**毕业。*（注：开启 `--xian-auto-fuse` 时，内置五元环最大匹配算法已强制锁死首尾配对，绝不会误切中间边。）*
  - **五灵根**：完整五元环，最终可融合成「**2 变异 + 1 基础**」（渡劫最高 `6.43x` 倍率）；第一刀任选一对相邻灵根，第二刀在剩余三条相连基础灵根中再选一对即可。

#### 两条手操防坑提醒

1. **融合前务必先花 `50` 灵石学完基底功法**：融合成功后角色失去对应的两条基础灵根，藏经阁将**永久无法再学习**那两系基础功法；但服务端切换装备功法（`xsEquip`）只检查是否已学会（`techs` 列表），不检查灵根是否仍在。只要融合前把两条基础功法先买到手（例如先学水系全屏追踪再合冰/风），融合后依然可以永久自由切换使用。*（开启 `--enable-xian` 时，程序会在自动融合前强制先学齐当前灵根功法。）*
2. **卡在「刚突破 / 刚升小层」的零修为窗口融合**：每次尝试融合固定消耗 `2` 颗培元丹 + `200` 灵石，基础成功率为 `55%`；若失败会有 `24` 小时冷却并额外扣除当前小层 `20%` 修为（`floor(xp * 0.8)`）。建议在刚升入新境界或新小层、当前修为接近 `0` 时尝试融合，可将修为折损降到接近零；避免在 `9` 层攒满修为准备冲关前点融合。

## 规则更新与目录结构

代码中未硬编码任何小岛物品或配方 ID，所有数值均在启动时从 `rules/pet-world-rules.js`（及修仙模块对应的 `rules/xs-xian-rules.js`）动态解析。若站点前端更新了规则文件，直接覆盖对应文件并重启进程即可生效。

```text
cli/               守护进程入口（live-daemon / shadow-daemon）与单步控制器
planner/           种植、工坊、出货、体力与出访联合规划求解
execution/         HTTP 限流与时钟校准、事务对账、出访调度、战斗配装模拟、可选修仙切片
model/             规则解析与资产估值
audit/             本地事务流水记录与复盘工具
rules/             游戏前端规则文件（小岛与大肥鱼修仙记）
test/              自动化测试集（74 项）
architecture.html  交互式系统架构与时序图谱（浏览器直接打开）
```
